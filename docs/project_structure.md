# Структура Django-проєкту

Проєкт побудований як модульна Django-система для підтримки процесу паркування автомобілів. Кожен застосунок відповідає за окрему частину бізнес-процесу.

## core

Відповідає за загальні сторінки системи:

- головна сторінка `/`;
- сторінка “Про систему” `/about/`;
- демонстраційна management command `seed_demo_data`.

`core` є вхідною точкою для користувача і містить базову інформацію для презентації дипломного проєкту.

## accounts

Відповідає за облікові записи користувачів:

- реєстрація;
- вхід і вихід;
- особистий кабінет;
- повідомлення про активні бронювання, оплату й доплати;
- helper-функції ролей;
- context processor для меню;
- команда `setup_roles`.

`accounts` пов’язаний із `reservations`, бо профіль користувача показує його бронювання, фінансовий стан і статуси оплати.

## parkings

Відповідає за парковки, типи паркомісць, паркомісця й тарифи:

- список парковок `/parkings/`;
- глобальний пошук місць `/parkings/search/`;
- детальна сторінка парковки з сіткою місць;
- моделі `ParkingLot`, `ParkingSpaceType`, `ParkingSpace`, `Tariff`.

`parkings` використовується в бронюваннях, dashboard, звітах і контролі доступу.

## reservations

Відповідає за бронювання паркомісць:

- створення бронювання;
- перегляд деталей бронювання;
- скасування бронювання;
- QR-код бронювання;
- облік базової вартості, доплати, фінальної суми та статусів оплати.

`reservations` пов’язаний із `parkings`, `vehicles`, `accounts`, `access_control`, `dashboard` і `reports`.

## vehicles

Відповідає за “Мій гараж”:

- список авто користувача `/vehicles/`;
- додавання авто;
- редагування авто;
- деактивація авто.

Автомобілі використовуються під час бронювання, щоб користувач міг швидко вибрати номер авто.

## access_control

Відповідає за контроль пропуску:

- сторінка перевірки QR-коду `/access-control/`;
- сторінка деталей бронювання для оператора;
- підтвердження в’їзду;
- підтвердження виїзду;
- журнал доступу `/access-control/logs/`;
- фільтри журналу;
- позначення оплати адміністратором.

`access_control` використовує модель `Reservation` і створює записи `AccessLog` для аудиту дій оператора або адміністратора.

## dashboard

Відповідає за адміністративну панель:

- Dashboard `/dashboard/`;
- генератор сітки парковки;
- керування списком парковок;
- керування паркомісцями;
- редагування паркомісць;
- керування тарифами.

Доступ до dashboard має тільки адміністратор або superuser.

## reports

Відповідає за звіти:

- сторінка звітів `/reports/`;
- фільтри за датою, парковкою і статусом;
- фінансові підсумки;
- CSV-експорт `/reports/export/csv/`.

`reports` використовує дані з `reservations`, `parkings` і `vehicles`.

## templates

Містить HTML-шаблони системи:

- `base.html` - базова структура, navbar, messages, sticky footer;
- `core/` - головна сторінка та “Про систему”;
- `accounts/` - вхід, реєстрація, профіль;
- `parkings/` - парковки, пошук, сітка місць;
- `reservations/` - бронювання, деталі, QR-код;
- `vehicles/` - гараж користувача;
- `access_control/` - контроль пропуску й журнал;
- `dashboard/` - адміністративні сторінки;
- `reports/` - звіти.

Шаблони використовують Bootstrap і спільні CSS-класи з `static/css/style.css`.

## static

Містить статичні файли проєкту.

Основний файл:

- `static/css/style.css`

У ньому зібрані спільні стилі для:

- page header;
- карток;
- статистичних блоків;
- таблиць;
- empty states;
- сітки паркомісць;
- мобільної адаптації.
